## 目标与背景

用户需求原文：

1. 拆分常驻采集服务 + TUI 客户端接入（属于重构）。
2. 完全按照目前 HTML 设计 Web 展示界面 + 接入 Web 容器。

TUI 和采集服务运行在 Ubuntu 宿主机，Web 运行在同机容器内。两种界面消费同一采集服务的数据，查看行为不增加采集任务；采集不再依赖交互终端会话存活。

本期仅供内网访问，不考虑此前讨论的外网设备接入、VPN、隧道、公共域名或外网身份认证。用户明确：Web 不做登录；网段和网络策略由部署环境负责，程序不管理这些配置。

已确认的主要行为：历史仍为约 60 秒，Web 实时展示、不回看；原 `joi-observer` 只连接常驻采集服务；连接失败后 TUI 报错退出、重新运行重试，Web 停留错误页、刷新重试，均不自动重连；统一监控配置修改后重启采集服务生效；两种界面的模型列表显示 `name`，详情显示 `served_model_name`；Web 的 Running/Total 省略容量分母，超量 GPU、模型和容器条目隐藏。

本文已确认决定优先于 HTML 的模拟行为及旧模块文档，包括移除 Web 的 180 秒历史/回看，以及调整旧 TUI 模型详情名称。完整决定记录见文末。

## 需求说明

### REQ-001 宿主机常驻采集服务与 TUI 客户端

**需求说明与预期行为**

- 采集服务在宿主机后台常驻，不要求 stdin/stdout 为交互终端。无人打开界面时仍按生效配置持续采集，统一维护最新指标、历史、采集状态和错误日志。
- `joi-observer` 默认进入 TUI 客户端，只连接常驻服务。客户端不隐式启动服务，不在连接失败时退回独立采集，也不自行持有硬件/Docker/vLLM 采集权限。
- TUI 的 `q`、正常退出、异常或终端会话断开只影响当前 TUI。采集服务和其他客户端继续工作。
- 多个本机 TUI 能读取同一个服务的结果；每个会话独立选择模型和主题。已有 TUI 的布局、最低尺寸、颜色、数字精度、导航和 60 秒扫描历史继续沿用当前基线；模型详情标题按共同约束 14 改为 `served_model_name`，模型列表仍显示 `name`。
- 初次连接及用户手动重新发起连接时，客户端获得同一生效配置对应的展示元数据及快照，不把旧名称/顺序与新指标混用。
- 服务重启后，客户端识别新的服务实例，不拼接重启前后的历史、不复用旧统计基线。已保留的最后画面不能被误认为新服务的有效数据。
- 采集器失败与客户端到采集服务的连接失败是两种状态，分别表达，避免一个来源失败被误报为整个服务失联。
- 服务未启动、初次连接失败或运行中连接中断时，TUI 报告连接错误并退出。已经进入全屏时先恢复终端，再输出可读的错误提示；不要求用户从已退出/损坏的全屏中寻找错误。用户重新运行 `joi-observer` 才发起新连接，服务自行恢复不能复活旧会话。
- 采集服务统一读取和校验监控配置。修改文件不会改变当前运行的采集对象或元数据，重启采集服务后才使用新配置；配置非法时沿用明确报错、不隐式回退的既有规则。TUI 客户端不通过自己的配置文件改变后台服务。

**边界与约束**

- 本项以现有能力的运行期重构为主，同时包含用户明确要求的 TUI 模型详情名称调整。除该名称映射及客户端连接/退出行为外，业务计算和 TUI 呈现保持原有语义。
- 当前同步 `snapshot()` 的无 I/O 约束继续成立；进程间数据获取不能阻塞逐帧绘制和按键响应。
- 支持以系统后台服务方式管理，配置仅在服务启动/重启时加载。服务命令、开机自启部署步骤、本机只读权限和重复实例防护由 R2 在既定单一采集服务边界内细化。
- TUI 连接错误后报错退出，只能通过重新运行重试；不增加错误界面内的重试键或自动重连。
- 保留并复用既有有效测试覆盖，包括配置、采集解析、调度与状态、错误日志、TUI 视图/导航/终端等。未变更功能的原有测试必须通过；因接口迁移或本文已确认的行为变化，可以调整或替换相应用例。不得通过删除、跳过或弱化断言掩盖重构回归，新增测试应补充原有覆盖。执行平台继续遵循共同约束 10。

### REQ-002 Neon Grid 只读 Web 看板与同机容器部署

**需求说明与预期行为**

- 以当前 `docs/design/joi-observer.html` 的 Neon Grid 为视觉基线，实现完整的正式浏览器页面：品牌与主机信息、主题切换、GPU、Host Resources、Storage、Docker、vLLM 模型列表和详情、底部服务入口。
- 桌面布局、面板关系、字体、配色、硬件条、数据强调和响应式方向遵循设计稿。展示真实数据和动态对象，不能把设计稿的 5 GPU、3 模型、容器名称、端口、利用率或主机时间作为生产固定值。
- Hologram / Moonlight 两主题以及模型选择作用于当前客户端。选中模型对应的 GPU 关联、各模型状态和指标来自采集服务。
- 模型列表显示 `name`、详情标题显示 `served_model_name`，缺省回退与 TUI 一致；Docker 条目显示配置 `id`。这些字段使用统一生效元数据，不从成功样本、URL 或 HTML 的示例别名猜测。
- 曲线采用主题主色描边，曲线下以同一主色由上向下逐渐透明填充；不采用主色到副色的双色渐变。
- 历史只展示最近约 60 秒并跟随新数据更新；不提供拖动回看、左右平移、历史时间范围选择或 180 秒缓存。移除设计稿中的回看控件和提示。
- 无观测、未知与不适用数据沿用既有业务语义；失败区间保留曲线缺口，不用平滑插值伪造缺失样本或把缺口变为零。
- 数据字段和单位以已实现的采集契约为准，例如 pooling 速率使用 `seq/s`。Running 和 Total 只显示真实计数，省略示例容量分母，不新增容量上限配置或未知分母占位；Total 继续使用采集服务的业务计算结果。
- GPU、模型和容器按现有来源/配置顺序显示面板容量内的条目，其余隐藏。超量不增加面板滚动、分页或“显示更多”功能，也不为了容纳所有条目撑高页面；隐藏对象仍参与后台采集，失败对象不被后续健康对象替换。正常响应式页面重排仍沿用设计稿。
- 空配置、首次加载、局部采集失败以及整体服务失联均应有明确展示，不通过隐藏异常对象制造健康画面。
- 初次获取数据失败或已加载页面的数据连接中断时，Web 停留在明确的错误页面，不继续把旧指标作为实时看板展示。页面及 Web 后台均停止自动重连，采集服务恢复后仍保持错误状态；用户刷新页面才发起新的数据连接尝试，无需为重试重建 Web 容器。
- 错误状态按浏览器会话保留：若一个用户刷新页面使共享后台数据通道恢复，其他已显示错误的页面仍等待各自用户刷新，不自行恢复。
- Web 以单独容器运行在采集宿主机上，读取 REQ-001 提供的数据能力；浏览器经该容器访问页面和只读数据接口，不直接连接采集服务或被监控的 vLLM/Docker 服务。
- 提供可在目标环境部署的容器构建/启动配置及必要的安装、启动、停止、升级、日志和连通性说明。网页资源不依赖 Codex 的 `window.openai` 或设计预览运行时，也不依赖访问外部 CDN 才能正常显示。

**边界与约束**

- 只实施 Neon Grid；不交付概念稿轮播、Amber Relay、Vector Matrix、设计调色工具或模拟故障切换控件。
- WebUI 等预留入口沿用设计稿的禁用占位，不增加服务集成；正式浏览器键位、提示与响应式尺寸由 R2 明确，不能保留暗示关闭后台采集或历史回看的无效操作。
- 仅内网使用，不开发登录、用户管理、外网接入或程序内网段限制；监听和端口等部署参数与网络策略责任应明确区分。
- 不把常驻采集服务移入 Web 容器。容器不使用 privileged 模式取得采集能力，不挂载宿主机 Docker socket 或整个宿主根目录。
- 不增加长期历史、下载导出、告警、通知或远程管理功能。
- Web 容器尚未运行、页面也尚未加载时，浏览器可以显示连接失败；不要求引入另一个服务托管自定义错误页。已加载页面的数据连接错误由页面明确呈现。
- 具体容器网络、数据通道、Web 框架和推送/轮询方式留给 R2，但必须满足单一采集源、只读和客户端故障隔离的业务要求。
