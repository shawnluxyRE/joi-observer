## R2-REV-004：监听就绪与采样启动缺少可执行的接口边界

原文档要求首次监听失败时零采样，但发布器只有 `run()` 自行绑定；服务没有明确的监听就绪入口，无法同时保证不重复绑定和成功绑定前不启动 Monitor。

处理：增加 `SnapshotPublisher.start()` 骨架，仅绑定，不读取 source、不采样；成功后重复调用不重绑。服务先 await start，再并发发布与采样；单独 run 在 NEW 时自调 start，已启动时复用监听。启动失败清理已取得资源并报安全 ServiceStartError，运行中发布故障继续沿用采集隔离规则。

已同步服务类图/启动时序、server/service 注释和以下黑盒：

- `test_publisher_explicit_start_binds_once_without_reading_source`。
- `test_service_bind_failure_never_starts_sampling_and_releases_resources`。

## R2-REV-005：新会话可能先收到过期发布缓存

如果编码长期在途而接受连接仍正常，最近已发布帧可能已超过失联窗口。原“新读者立即取得缓存”的规则没有限制该缓存发布年龄，可能使手动新会话短暂显示过时状态。

处理：首帧开始发送前用宿主 monotonic 与 `published_at` 比较，超过既有五秒期限的缓存不作为首帧发送。该连接等待下一次正常发布，等待包含在客户端原首帧总期限内，不延长期限、不重连，不因为有新读者额外调用 source 或采样。提供 `clock` 注入以做离线边界验证。

这只控制服务端首帧缓存选择，不承诺完成安装时的发布年龄恒小于五秒；读写和解码仍受原完整帧预算约束。也不使用来源 sampled_at 判定传输时效：慢采样和局部 STALE 可以通过健康心跳继续显示。

已同步 server 注释、整体/服务/IPC/TUI 文档；新增 `test_new_reader_waits_for_normal_publication_when_cached_frame_is_expired`，并将原发布测试的时间夹具与注入时钟匹配，保留其数值/序号/隔离断言。

## R2-REV-006：已有客户端契约缺少对应黑盒

原契约要求 state revision 和 published_at 不倒退，并允许相同 revision 的心跳更新自然过期历史，但之前测试主要覆盖身份、metadata 和传输序号。

处理：补两个倒退负向参数场景，以及同 revision、新 sequence 的历史过期正向场景。正向预期要求新缓存实际替换，同时旧不可变引用保持原历史；不能按 revision 相同直接忽略心跳。这是补齐既有行为验证，没有改变状态数学。

## 复查确认与边界

- published_at 先取时刻、随后同一事件循环无 await 读取 State，采集提交不能插入同步段；历史下边界裁剪与协议窗口一致。
- GPU 动态注册、inventory 提交和更新通知由 Monitor 协调；设备身份、顺序和历史在完整快照中传递，不要求客户端独立发现。
- 配置冻结、实例锁 inode 保留、重启生成新身份、无自动重连、终端先恢复再诊断和发布故障不停止采集，图文与接口一致。
- 大快照总内存随实际对象增长；有界 IO/队列不等于总内存恒定。worker 的 GIL/执行隔离、取消、迟到结果、退出预算和实际吞吐仍须 R4 测量，不能把线程或异步 read 本身当成已验证的响应性。
- 生产采样 1～60 秒、采集超时原范围、模型详情名称规则均保留。原配置解析及视图仍待 R4 实现这些已确认变更，未弱化相应失败预期。
